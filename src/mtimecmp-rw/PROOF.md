# Proof: CLINT mtimecmp read/write register probe

## What was built

`src/mtimecmp-rw/`: a bare-metal RISC-V program that verifies, on the QEMU
`virt` board, that the CLINT `mtimecmp` register for hart 0 (`0x02004000`) is
a plain read/write MMIO register. Two files, sharing only `src/boot.S` and
`src/uart.c` with the other demos. Exactly one mechanism is under test:
whether written 64-bit patterns come back from mtimecmp unaltered, and
whether the writes themselves neither trap nor deliver an interrupt.

- `rw_main.c`: boots into M-mode on hart 0, installs the trap vector,
  writes 0 to `mie` (every machine interrupt enable bit clear, including
  `mie.MTIE`), then writes three patterns to mtimecmp with two 32-bit
  stores each (low word, then high word): `0x0`,
  `0x123456789ABCDEF0`, `0xFFFFFFFFFFFFFFFF`. Each pattern is read back
  with two 32-bit loads and required to match exactly. After each
  write the program samples `mip` and publishes the MTIP bit. It then
  writes mtimecmp back to all-ones (the disarmed state) and publishes
  the disarm readback, the trap record, and the verdict.
- `rw_trap.S`: the M-mode trap handler. Any trap is unexpected (plain
  MMIO in M-mode with `mie` = 0), so the handler records mcause/mepc/
  mtval and bumps a trap count in `rw_save`, then parks the hart. A
  printed `PASS` therefore implies the trap count was zero.

## Ground truths

- The CLINT memory map on the virt board puts hart 0's `mtimecmp` at
  `0x02004000` (SiFive CLINT layout: `mtimecmp` for hart 0 at offset
  `0x4000` from `0x02000000`), confirmed by the register accepting
  writes in this run.
- The `mie` CSR gates all machine interrupts: with `mie` = 0, a set
  `mip.MTIP` cannot be delivered, regardless of `mstatus.MIE`.
- `mtime` is a live counter; with `mtimecmp` = 0, `mtime >= mtimecmp`
  holds, so the hardware sets `mip.MTIP`. The large patterns leave
  `mtimecmp` far above the running `mtime`, so MTIP stays clear.

## Measured results (3 runs, QEMU 8.2.2, byte-identical output)

Build: `make mtimecmp-rw.elf` compiles `src/boot.S`, `src/uart.c`,
`rw_trap.S`, and `rw_main.c` with the standard flags
(`-march=rv64imac_zicsr -mabi=lp64`); `src/boot.S` links first so
`_start` lands at `0x80000000`, where QEMU's `-kernel` loader starts
execution. The run logs are in `bench-logs/` (run-1/2/3.txt); all
three are byte-identical and the QEMU process exited 0 each time.

| Trial | Written | Read back | Equal | mip.MTIP after write |
|---|---|---|---|---|
| 0 | `0x0000000000000000` | `0x0000000000000000` | yes | 1 (pending) |
| 1 | `0x123456789abcdef0` | `0x123456789abcdef0` | yes | 0 (clear) |
| 2 | `0xffffffffffffffff` | `0xffffffffffffffff` | yes | 0 (clear) |
| disarm | `0xffffffffffffffff` | `0xffffffffffffffff` | yes | 0 (clear) |

- Trial 0's pending MTIP is the honest expected result: the write
  was `0x0` while `mtime` was running, so `mtime >= mtimecmp` pended
  the timer interrupt, but with `MTIE` = 0 no trap fired (trap count
  stayed 0). Pending-but-undelivered is exactly what the gate on
  `mie` promises.
- Trap record: count = 0, mcause = 0, mepc = 0, mtval = 0. No write
  or read touched the trap handler.
- 6 checks, 0 mismatches, FNV-1a checksum `0xbe715111eb42d62b`
  (over the three written values, readbacks, mip samples, the
  disarm readback, and the trap count; no live `mtime` values are
  fed into it, so it is identical across runs), `RESULT: PASS`.

## Why the access form is 32-bit

64-bit accesses to CLINT registers are never issued: they fault on
this emulator (observed with the `msip` register in `src/msip/`, and
relied on by `src/mtimecmp-delta-tracks-mtime/` and
`src/mtime-write/`). `mtimecmp` is not a free-running counter, so
the low/high split cannot tear; the register holds the written
value after both stores complete.

## What this does not claim

- Single-hart only: the register belongs to hart 0; nothing here
  says anything about other harts' `mtimecmp` registers.
- The probe does not measure timer delivery latency or interrupt
  accuracy; the companion `src/mtimecmp/` module does that over
  1000 armed trials, and `src/mtimecmp-oneshot/` covers the disarm
  path.
